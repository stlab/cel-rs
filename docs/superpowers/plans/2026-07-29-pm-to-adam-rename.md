# pm → Adam Rename Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Drop the `pm`/`property-model` nomenclature workspace-wide and rebrand the
property-model system as "Adam" (crate: `adam-rs`, matching the `cel`/`cel-rs` naming
pattern), covering crates, the VS Code extension, workspace config, and living docs.

**Architecture:** This is a mechanical, deterministic identifier rename, not new
functionality. Every occurrence of a small set of tokens is replaced 1:1 per the mapping
table below. No behavior changes; verification is "does it still build/test/lint clean"
plus a final grep sweep for anything the mapping missed.

**Tech Stack:** Cargo workspace (Rust), npm/tsc (VS Code extension), git (directory
renames via `git mv` to preserve history).

## Global Constraints

- Drop "Adam2" — the product name is plain **Adam** / **adam** everywhere. (User decision,
  reversing an earlier "Adam2" proposal.)
- `adam-rs` is the Rust crate name for the property-model library, mirroring how `cel-rs`
  is the crate name for the CEL runtime — the "-rs" suffix belongs on package names, not on
  every internal symbol (internal identifiers use plain `adam`, e.g. `adam_lang`, not
  `adam_rs_lang`).
- The generic English phrase "property model(s)" (the bipartite cells/relationships
  concept) is **not** a naming violation and is left as descriptive prose wherever it
  appears that way (e.g. `property-model/src/lib.rs`'s "constraint graphs" description,
  crate `description` fields in Cargo.toml). Only the branded/abbreviated forms
  (`pm-lang`, `pm-lsp`, `PmParser`, `PmAstParser`, `property-model` as a crate name, the
  `PM` alias, `property_model` as a Rust path) are renamed.
- Dated historical documents under `docs/superpowers/plans/**`, `docs/superpowers/specs/**`,
  and the dated root handoff files (`docs/superpowers/2026-*-handoff*.md`,
  `docs/superpowers/2026-07-20-phase-3-vscode-extension-handoff.md`) are **left untouched**.
  They're point-in-time records of already-merged work; rewriting their "pm-lang" mentions
  would falsify history. `docs/VISION.md`, `README.md`, and `CLAUDE.md` are living docs and
  **are** updated.
- `Cargo.lock` and `editors/vscode-pm-lang/package-lock.json` are not hand-edited — they're
  regenerated by `cargo build` / `npm install` after the manifest renames.
- The `.adm2` file extension is **not** renamed. Its rationale (avoid colliding with VS
  Code's built-in `.pm` → Perl association) is independent of the "Adam2" naming that's
  being dropped, and changing a user-facing file extension is out of scope for this
  cleanup unless asked.

| `pm-lang` | `adam-lang` | crate/dir/language-id name (also fixes `vscode-pm-lang` → `vscode-adam-lang`, `source.pm-lang` → `source.adam-lang`) |
