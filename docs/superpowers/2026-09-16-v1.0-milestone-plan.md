# v1.0 Milestone — Independent Work Groups

Original grouping as of 2026-09-16; completion reviewed on 2026-10-06 against GitHub issue/PR
status, repository code, and implementation handoffs. This organizes the 12 issues that were
open in the `v1.0` milestone into groups that can be worked on independently (each group in its own worktree/PR
sequence) with minimal expected merge conflict, and orders the groups so that anything other
groups build on lands first. Within a group, issues are listed in the order they should land
if the group's issues touch overlapping code (noted per group); across groups with no listed
dependency, the groups themselves can proceed in parallel.

Checked items are implemented or explicitly resolved as noted; a closed duplicate or
not-planned issue does not mean its original proposal was implemented. Partial work remains
unchecked. Group 3 is complete locally but is not yet merged; the other
completed implementations below are merged.

Gaps found in `docs/VISION.md`'s roadmap that had no tracking issue were opened separately
during this review: #218 (query pinned cells), #219 (cell "memory"/unlink behavior), and #220
(view-constraint sheets, blocked on #109/#110/#111). They are not v1.0-milestoned and are not
included in the groups below.

## Group 1 — adam-rs planner cleanup (do first)

**Complete, merged:**

- [x] #187 — adopt Kahn's topological sort, prune the acyclic search, and factor
  `propagate()` duplication. Merged in #237 on 2026-09-26.

**Why first (historical):** #187 touches every file Group 2's issues also touch
(`planner.rs`, `matching.rs`, `release.rs`, `digraph.rs`, `scc.rs`, `seed.rs`, and `sheet.rs`'s

avoids those changes being written against, and then needing rebasing off, machinery this issue
deletes or restructures.

## Group 4 — cel-parser/cel-runtime language surface (independent of Groups 1–3)

**Incomplete, in the original landing order:**

- [ ] #110 — arrays are implemented, including typed literals; `.name(...)` method-call
  syntax is not. The current postfix grammar supports calls and numeric tuple indices only.
- [ ] #10 — first-class closure values and typed closure literals exist, but the closure
  design defers general application of arbitrary closure-valued expressions. Do not treat
  this partial implementation as completion of the open first-class-functions issue.
- [ ] #111 — geometry and affine-transform value types remain outstanding, including
  their dependency on method-call syntax.

**Why grouped/sequential:** all three land in the same core parser/runtime files
(`cel-parser/src/lib.rs`, `op_table.rs`, `cel-runtime`'s segment/value-type machinery), so
they're sequenced as one track to avoid conflicting rewrites of the same op-dispatch and
grammar code. #111 has a hard dependency, stated in its own issue text: it needs method-call
syntax (clamping operations on point/size/rect/`TranslateScale`) from #110. #10 (first-class
functions) has no stated dependency on #110, but shares enough surface (op-table overloading,
grammar entry points) that sequencing it between #110 and #111 avoids a three-way conflict;
it could equally be reordered first if that better matches whoever picks up this track.
Fully independent of Groups 1–3 (different crates entirely — no shared files with `adam-rs` or
`begin`).
